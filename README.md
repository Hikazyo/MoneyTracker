# MoneyTracker 记账本

一个**原生 Android 单机记账应用**。所有账目只保存在这台设备上——应用**没有申请任何系统权限，连 `INTERNET` 都没有**，因此「不会上传你的数据」不是一句承诺，而是系统层面的既成事实。


```
Kotlin 2.3.20 · Jetpack Compose · Room 3 版 schema · minSdk 24 / targetSdk 36
```

## 功能

### 记账

- **记一笔**：自带数字键盘，金额用「分」存整数，永不使用浮点
- **账单列表**：按月切换，当日小计，点任意一笔即可修改或删除
- **统计**：分类占比环形图 + 近月收支趋势（手绘 Canvas，不引图表库）
- **预算**：总预算 + 分类预算，超支预警；分类预算之和超过总预算时给出提示

### 导入外部账单

支持**微信支付账单**与**支付宝账单**，CSV 与 Excel（`.xlsx`）都认。

导入前**必须先看预览**：解析出多少笔、跳过多少笔及原因、自动匹配了多少分类、未匹配的归到哪里。重复导入同一份账单不会产生重复账目（靠数据库唯一索引 + 排序规则，不是「先查后插」）。

### 截图记账

手里的账单是截图？直接选图就行：设置页 →「从截图记账」→ 选图 → 预览 → 导入。

- 支持**微信账单**（浅色/深色）、**支付宝账单**（简体/繁体）、**银行流水**
- 一次可选多张；一屏有多笔会**逐笔**列出
- 预览里金额只读（实测接近 100% 准确），**日期与分类可改**——OCR 的日期最容易出错
- 「疑似资金划转」（自动攒 / 转账 / 退款）默认不勾选，避免把「钱换个口袋」记成消费
- 同一张截图重复导入不会重复记账（`SHOT:<图片哈希>:<行序号>` 去重）
- 识别用 ML Kit **捆绑模型**，全程在本机完成，**不联网、不需要任何权限**

> 识别结果**永远不会直接入库**，一定先过预览。OCR 一定会错，让用户看一眼是唯一的防线。

### 导出与备份

- **导出 CSV**：带 UTF-8 BOM，Excel 打开中文不乱码
- **创建备份 / 从备份恢复**：完整的 JSON 备份，支持**可选口令加密**（PBKDF2 20 万次 + AES-256-GCM）
- 全部走系统文件选择器（SAF），**不需要存储权限**，保存位置由你决定

### 分类管理

28 个内置分类（20 支出 + 8 收入），自定义分类可改名、换图标、改方向。

编辑范围按分类的实际情况区分——**不能改的项也会显示出来并说明原因**，而不是直接隐藏：

| 分类 | 名称 | 图标 | 收支方向 |
|---|---|---|---|
| 新建 | ✅ | ✅ | ✅ |
| 内置分类 | ✅ | ❌ | ❌ |
| 自定义 · 有账目 | ✅ | ✅ | ❌ |
| 自定义 · 无账目 | ✅ | ✅ | ✅ |

内置分类的图标被锁死是有原因的：`iconKey` 是**账单导入自动归类的锚点**，改了它，导入时那类账目就再也匹配不上分类，而且不会报错——只会静默落进兜底分类。

## 隐私与安全

### 应用没有任何联网能力

- **零权限**：合并后的发布清单里**没有任何一条 `uses-permission`**（只有 AndroidX 自动生成的一条 `signature` 级自定义权限，不授予任何系统能力）。截图识别用的 ML Kit 会在它自己的清单里声明 `INTERNET` 与 `ACCESS_NETWORK_STATE`，构建时已用 `tools:node="remove"` 从合并结果中剔除——**没有 `INTERNET`，进程连 socket 都建不出来**
- **第三方功能库只有两个**：SQLCipher（数据库加密）与 ML Kit 文字识别（**捆绑模型版**：模型随 APK 安装，识别全程在本机，不下载、不上传）。依赖表里没有广告、统计、崩溃上报、推送
- **零日志泄露**：全部源码检索 `Log.d / println / printStackTrace` → 0 命中
- **零对外共享**：没有 `ACTION_SEND`、没有剪贴板、没有外跳浏览器、没有 FileProvider

### 数据加密

- **数据库**：SQLCipher（AES-256）。口令为随机 32 字节，用 Android Keystore 里的密钥封装后保存，密钥材料不出系统
- **备份文件**：可选口令加密。AES-GCM 自带完整性校验，口令错误或文件被改动都会在解密时报错，**不会解出一段垃圾数据再拿去覆盖账本**
- **明文库自动迁移**：从旧版本升级时会就地加密已有数据，全程保留回滚点，任何时刻磁盘上都至少有一份完整可读的数据

### 数据不会随系统备份离开设备

系统备份进程**不需要应用拥有 `INTERNET` 权限**就能把数据传走——这是「只存本机」这句承诺唯一可能被绕开的地方。

### 其它

- `FLAG_SECURE`：账本不进入「最近任务」缩略图、截图与录屏
- 口令解不开时显示专门的说明页，**绝不静默重建空数据库**——那会让用户以为数据被自己弄丢了
- 导入体积上限 32 MB（边读边计数）、xlsx 单条目解压上限、CSV 行列上限
- 恢复时校验金额、时间、枚举与文本长度，坏数据整笔回滚而不是写一半

### 加密挡不住什么

| 场景 | 挡得住吗 |
|---|---|
| 单独拿走数据库文件（取证镜像、`adb backup`、拷走文件） | ✅ 只有密文 |
| 未加密的整机备份、被同步到别处的数据目录 | ✅ 只有密文 |
| 系统云备份 / 换机迁移 | ✅ 已在清单里显式排除 |
| 设备已解锁、且能在本应用进程里执行代码（例如已 root） | ❌ 它可以直接请求 Keystore 解密 |

也就是说，加密把「拿到文件就能读」提升为「拿到已解锁的设备才能读」。要连后者也挡住，需要口令由用户输入且不落盘 + 生物识别——那是「应用锁」，目前**没有做**。

> 顺带一提：因为开了 `FLAG_SECURE`，本仓库**没有界面截图**——截屏会被系统拦掉。这算是这个安全设置的一点副作用。

## 构建与运行

### 环境要求

| 项 | 版本 |
|---|---|
| JDK | 17（用于编译；Gradle 本身可用更高版本运行） |
| Android SDK | Platform 36、Build-Tools 36.1.0 |
| Gradle | 9.1.0（随 wrapper） |

### 命令

```bash
# 调试包
./gradlew :app:assembleDebug

# 发布包（开启 R8 代码压缩与资源压缩）
./gradlew :app:assembleRelease

# 安装到已连接的设备
./gradlew :app:installDebug
```

### 关于签名

发布签名从**工程目录之外**读取，按这个顺序查找：

1. `-Pkeystore.properties=<路径>`（CI 用）
2. `%USERPROFILE%/.android-keys/moneytracker/keystore.properties`（推荐位置）
3. `<工程根>/keystore.properties`（兼容旧布局）

**三者都没有时，release 会回退到 debug 签名**——所以 clone 下来就能直接构建，不会卡在「找不到密钥库」。自己发版时才需要准备密钥：

```bash
keytool -genkeypair -v -keystore moneytracker-release.jks -storetype PKCS12 \
  -keyalg RSA -keysize 2048 -validity 10000 -alias moneytracker \
  -dname "CN=MoneyTracker, OU=Personal, O=Personal, L=Unknown, ST=Unknown, C=CN"
```

> ⚠️ 密钥文件丢失 = 已安装的用户**永远无法再收到升级**（自签分发无法平滑换签）。请单独备份。

### 安全打包

```powershell
powershell -ExecutionPolicy Bypass -File tools/make-dist.ps1 -VerifyOnly   # 只检查
powershell -ExecutionPolicy Bypass -File tools/make-dist.ps1               # 打包
```

它会排除密钥、口令、安装包与构建产物，并在打包前**独立复核**包含列表里没有任何敏感项。手动右键压缩不会帮你过滤——本项目就因此出过一次事故（分发包里同时含私钥与明文口令）。

## 测试

**480 个测试**（322 个 JVM 单元测试 + 158 个插桩测试）。

```bash
./gradlew :app:testDebugUnitTest          # 单元测试（不需要设备）
./gradlew :app:connectedDebugAndroidTest  # 插桩测试（需要模拟器或真机）
```

测的重点是**容易错又不容易发现**的地方：

- **金额**：分↔元换算、求和、预算进度——全部有纯单元测试
- **账单解析**：CSV 与 xlsx 各一套，样本贴近真实文件；xlsx 解析器的测试用内存里现拼的真 xlsx，能精确控制单元格类型（跳格、内联字符串、科学计数法）
- **数据库迁移**：`MigrationTestHelper` 在真实 SQLite 上验证，包括「迁移后 schema 与实体对不上」这类只在用户升级时才暴露的问题
- **加密**：口令解不开时是否拒绝降级、错误口令是否被拒、密文被改动是否被检出、**明文库迁移是否保留 `PRAGMA user_version`**
- **结构性约束**：内置分类不许重名/共用 iconKey、每个 iconKey 都要有图标、分类猜测规则的关键词不许重复——这些「改错了也不报错」的地方都由测试兜住

## 项目结构

```
app/src/main/java/com/moneytracker/app/
├── MainActivity.kt              入口（FLAG_SECURE、启动自检）
├── MoneyTrackerApp.kt           手动 DI 容器（未引入 Hilt）
├── Navigation.kt                4 个页签 + 二级页面
├── data/
│   ├── model/                   金额、月份、方向、趋势聚合
│   ├── db/                      实体、DAO、种子数据、迁移
│   ├── repository/              唯一的数据入口
│   ├── importer/                账单解析（CSV / xlsx / 编码嗅探 / 分类猜测）
│   ├── export/                  CSV 导出
│   ├── backup/                  备份编解码 + 可选口令加密 + 字段校验
│   ├── security/                数据库加密与明文库迁移
│   └── io/                      SAF 文档读写（含体积上限）
└── ui/
    ├── ledger/ statistics/ budget/ edit/   四个主页面
    ├── categories/ importer/ settings/     管理类页面
    └── components/ theme/                  共用组件与主题
```

`data/` 不依赖 `ui/`，`ui/` 只通过 `LedgerRepository` 接口取数据。

| 用途 | 选型 |

| 语言 / UI | Kotlin 2.3.20、Jetpack Compose（BOM 2026.03.01）、Material 3 |
| 导航 | Navigation 3 1.0.1 |

## 一些设计取舍

完整的记录见 [`DESIGN.md`](DESIGN.md)，这里只挑几条有代表性的：

**金额永远不用浮点。** 全项目以「分」为单位的 `Long` 存储，方向由独立字段决定，而不是用正负号。浮点无法精确表示小数，累加几千笔账之后误差会实际显现。

**分类预算用两张表，而不是一张表加可空字段。** SQLite 的唯一索引对 `NULL` 不生效，一张表存「总预算 + 分类预算」时，总预算那行的分类字段为 `NULL`，唯一约束就形同虚设。

**「删除分类」是归档而不是真删。** 账目对分类是外键 `RESTRICT`，真删会让历史账目失去归属。归档保留引用，历史记录与统计都完整。而名下**没有**账目的自定义分类才给「删除」——此时归档与删除的唯一区别是能不能撤销，并列两个按钮只会让用户停下来想「差在哪」。

**导入去重靠数据库唯一索引 + `INSERT OR IGNORE`，不是「先查后插」。** 后者在并发下有竞态，而用户把同一份月度账单导两次是很常见的事，重复记账会直接毁掉统计。

**种子数据分成「首版」与「新增」两份。** 种子只在首次建库时写入，已安装用户的库早就建好了。只往种子列表里加分类而不写迁移，结果是「新装用户有、升级用户没有」，**而且没有任何报错**——这是最难查的一类不一致。

**Navigation 3 1.0.1 没有导航项级的 ViewModel 作用域。** `viewModel {}` 会落到 Activity 作用域并在多次导航间复用，于是「编辑页」的状态会残留，表现为「第二次进入编辑页立刻自己弹回去」。编辑页因此改成了普通状态持有类，由界面 `remember(entryId)` 创建。

## 已知限制

- **没有应用锁**。拿到已解锁手机的人可以直接浏览全部账本；加密只挡住「单独拿走文件」这条路径
- **没有多账户/多账本**，也不支持现金/微信/支付宝这类「账户」概念
- **没有云同步**，这是刻意的（见上）
- **不支持 `.xls`**（Excel 97-2003 老格式），微信与支付宝导出的都是 `.xlsx`
- **截图识别只发 ARM 包**（arm64-v8a / armeabi-v7a）：识别模型随包安装，四套 ABI 会让安装包多出 41 MB。x86 设备（多为模拟器）装不了 release 版
- **截图识别会出错**：商户名常有错字，「昨天/今天」这类相对日期容易识别失败；滚动后**重叠的两张截图**，重叠的几笔会重复，请在预览里取消勾选
- **`targetSdk 36`**，在 Android 16 上验证；`minSdk 24` 意味着 Android 7.0 及以上可安装
- 无障碍支持不完整：两个图表（环形图、趋势条）没有 `semantics` 描述，读屏用户读不到数据
